### Inferences
- The MIT parts (the bulk of the mod and the Python MCP server) can be reused in Claude Crew freely, as long as both copyright notices (factorio-mcp contributors and Matteo Mekhail) are kept.
- `scripts/route/` (GPL-3.0-or-later by the author's own declaration) and `calc/` (AGPL) are the license hazards. A private, undistributed Claude Crew isn't bound by GPL copyleft. However, handing the mod zip to friends so they can join multiplayer is arguably distribution. A Claude Crew mod that includes `route/` would then have to be distributed under GPL-compatible terms. The safest path is to borrow route/ *ideas* (A* over (tile, direction), forced-ghost legality) and write the code fresh, or to ship route/ as a separate GPL mod.
- Because the repo root has no LICENSE, `lpf/` (renderer, simulator), `scripts/` and `docs/` are all-rights-reserved by default. Read them for ideas, but don't copy code from them.
- The project is very young and has a bus factor of one. No outside users or contributors are visible.

## 2. Architecture: planner, workers, board, models, idle time, verification

### Takeaway
There is **no orchestrator code** in the repo. The "planner" is the user's interactive Claude Code main session (Opus), with no character. Workers are Claude Code subagents (Sonnet, mostly medium effort) launched with the Agent tool and resumed with SendMessage. Each worker drives one character by calling `scripts/fa <character> <tool> '<json>'` through Bash. Work is assigned in **prose** sections of a shared markdown `board.md`, not as structured tasks. Workers act through per-step LLM tool calls whose tools are mod-side macro-actions (pathfinding walk, build_plan of up to 100 steps, queued jobs), and they write their own Python layout generators during the run. Verification is done by the planner with read-only RCON scripts and by worker self-reports. There are no machine-checked done conditions.

### Inferences
- Compared with Claude Crew, this is "Claude Code as the orchestrator". Scheduling, retries, cost tracking, task structure and done checks all live in the human-supervised Opus session's judgment plus markdown files. Its orchestration is less mature than Claude Crew's coordinator, scheduler and controller. Its game-side tooling is more mature.
- Every worker step costs an LLM turn (Sonnet medium). Claude Crew's "deterministic controller, model only on exceptions" design avoids this cost. LPF instead amortises it by making each tool call a large macro (build_plan, build_blueprint up to 1000 entities, run_plan chains).
- The "up to 16 agents" figure is a rules cap. In practice runs 1–3 used ≤4 workers and run 4 used ≤6, limited by API rate limits and the 5-hour session window.

### Gaps
- The planner's own prompt and Claude Code configuration aren't published, so how it decides assignments is known only from board.md output.
- No per-agent token counts or tool-call logs are published. The mod's rpc-log lives in gitignored `runtime/`.

## 3. Legit play (verified in source)

### Takeaway
Fair play is strongly enforced in the mod. Walking uses the engine pathfinder plus per-tick `walking_state` at normal speed. Mining uses the engine's own `mining_state` with vanilla timing. Crafting goes through the engine queue (`begin_crafting`). Every map action first walks into `reach_distance`/`build_distance`/`resource_reach_distance`. There is **no `teleport` anywhere in the mod**. Placement is instant once in reach, as in vanilla, with a manual build check. A few "instant actions" skip reach: research, equip, chest/landing-pad requests, train schedules, and platform ghosts (remote-view-like). The planner had raw RCON access, and it abused that access in run 4.

### Cited Findings
- `grep -rn teleport` over the whole vendored mod returns nothing. [src] — [LPF/factorio-mcp/mod/factorio-mcp](https://github.com/StevenLi-phoenix/llm-play-factorio/tree/main/factorio-mcp/mod/factorio-mcp)
- Walk (`scripts/actions/walk.lua`): `local SPEED_TILES_PER_TICK = 0.15 -- character running speed`, `c.surface.request_path({...})`, and each tick `c.walking_state = { walking = true, direction = direction_toward(pos, goal) }` with the comment "walking_state only lasts one tick, so it must be re-set every tick". UPSTREAM.md describes the stuck and deadline rules: "no closer to its current waypoint for 6 s… deadline of 4× the straight-line walking time + 30 s", and "Only a hop of 16 tiles or less may still be walked straight". The mod setting `factorio-mcp-pathfinder-budget` (default 4) multiplies the engine's pathfinder work per tick (a map-settings change). [src] — [walk.lua](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/mod/factorio-mcp/scripts/actions/walk.lua), [UPSTREAM.md](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/UPSTREAM.md)
- Reach (`scripts/actions/approach.lua`): `function M.ensure(task, c, target_pos, reach) if dist_sq(c.position, target_pos) <= reach * reach then … walk.begin(a.walk, c, a.target, math.max(reach - 0.5, 0.5))`. It is called with `c.build_distance` (place), `c.reach_distance` (transfer, rotate, set_recipe…) and `c.resource_reach_distance` (mine). [src] — [approach.lua](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/mod/factorio-mcp/scripts/actions/approach.lua), [build.lua](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/mod/factorio-mcp/scripts/actions/build.lua), [transfer.lua](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/mod/factorio-mcp/scripts/actions/transfer.lua)
- Place (`build.lua` `M.place.tick`): approach to `build_distance`, fail if `items.count(c, task.item) == 0`, step out of the footprint, `can_place_entity{… build_check_type = defines.build_check_type.manual}`, then `create_entity` and `c.remove_item(items.spec(task.item, 1))`. Fast-replace returns the old entity to the inventory via `refresh.mine({inventory = inv})`. [src] — [build.lua](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/mod/factorio-mcp/scripts/actions/build.lua)
- Mine (`mine.lua`): "The engine mines (selected entity + mining_state, like a player)", with `c.update_selected_entity(mp)` and `c.mining_state = { mining = true, position = mp }`. The fallback is a script timer of vanilla length: `hand_mining_ticks = ceil(mining_time*60/(base*bonus))` with base 0.5, "measured live: 0.496 iron ore/s". Upstream was "2× too fast" and the fork fixed it. Deconstruct uses the same formula. [src] — [mine.lua](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/mod/factorio-mcp/scripts/actions/mine.lua), [deconstruct.lua](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/mod/factorio-mcp/scripts/actions/deconstruct.lua)
- Craft (`craft.lua`): "hand-crafting via the character crafting queue", `c.begin_crafting({ count = count, recipe = task.recipe })`, polled through `crafting_queue_size`. Cancel calls `c.cancel_crafting`, which refunds ingredients. Production statistics for player-less characters are logged with `on_flow`. `build_plan` has `auto_craft` on by default. [src] — [craft.lua](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/mod/factorio-mcp/scripts/actions/craft.lua), [build_plan.lua](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/mod/factorio-mcp/scripts/actions/build_plan.lua)
- Fog of war (`vision.lua`): the mod keeps its own explored-chunk set "because the engine never charts for characters without a player". Perception is filtered by it, and "walk goals must be explored or within 64 tiles". — [UPSTREAM.md](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/UPSTREAM.md)
- Removed upstream for fairness: "1.6× movement-speed setting", "`deliver_items`; reading players' inventories and cursors", starter blueprint books. — [UPSTREAM.md](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/UPSTREAM.md)
- Instant, reach-free actions: `chest_requests` (`space.lua` finds the requester chest with `find_entities_filtered` and sets logistic sections without any distance check), `start_research`, `equip`, `set_train_schedule`, `exit_vehicle`, `respawn`, and the platform tools. The platform tools place ghosts the hub builds "as in remote view", with reach "about 10 tiles from (0,0)" when standing in a hub. [src + claim] — [space.lua](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/mod/factorio-mcp/scripts/space.lua), [space-tooling.md](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/docs/space-tooling.md)
- Space travel uses engine mechanics: `silo.launch_rocket({type = defines.cargo_destination.station, station = hub}, character)` and `hub.create_cargo_pod()` + `pod.set_passenger(character)`. Note: "A character that arrived by rocket cannot be set as passenger or teleported… The drop tool therefore re-creates the parked body (same name record, same inventory)." [claim, tested-facts doc] — [space-tooling.md](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/docs/space-tooling.md)
- Blueprint provenance gate: `import_blueprint`/`build_blueprint` refuse strings unless they were exported from the map or registered from the agent's in-run layout (`bp_registry.lua`, on by default). — [factorio-mcp README](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/README.md)
- No raw console commands for workers: "Only the `scripts/fa` CLI touches the game. No RCON, no console commands" (playbook rule). The planner and helper scripts, however, use `/silent-command __factorio-mcp__` (`park_character.py`, `kpi.py`). — [PLAYBOOK.md](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/docs/run4/PLAYBOOK.md), [park_character.py](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/scripts/park_character.py)

### Inferences
- These legit-play rules match or exceed Claude Crew's (pathfinding walk, reach, real inventory, real crafting time), and they add fog of war and a blueprint-provenance gate. The re-creation of a character's body on `drop_to_planet` and the reach-free requests are minor gray areas.
- Enforcement of "the planner never acts" is a prompt rule, not a technical control. Claude Crew's characterless coordinator could enforce it technically by having no write RPCs.

### Gaps
- Deconstruct timing for large entities and `fight`/`defend_area` fairness were not checked line by line.

## 4. Multiplayer with humans

### Takeaway
The LPF fork is designed **against** human co-play. A default-on mod setting "humans spectate" puts every joining player into the spectator controller and **destroys their character, items included**. Humans can chat, and agents see that chat in their news footer, but there is no command parsing (no @name/@all routing) and no human-build protection logic. Upstream linsyking/factorio-mcp lacks the spectator lock. There, humans can play alongside, and agents read human chat and can `follow_player`, but there is still no command protocol.

### Cited Findings
- `spectators.lua` header comment: "Humans spectate. Agents are the only ones allowed to change the map; a human who joins the server to watch is put in the spectator controller… Their character… is DESTROYED, items included". Code: `player.set_controller({ type = defines.controllers.spectator })` and `body.destroy()`. It runs on join, at mod start and in a 5-second sweep, and the setting `factorio-mcp-humans-spectate` defaults to on. [src] — [spectators.lua](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/mod/factorio-mcp/scripts/spectators.lua)
- `spectators.lua` exists only in the LPF fork, not in linsyking `044d46c` (directory diff). [src] — [linsyking/factorio-mcp tree](https://github.com/linsyking/factorio-mcp/tree/main/mod/factorio-mcp/scripts)
- Chat: `chat.on_console_chat` logs every player message (`player = player.name, text = event.message`). Agents read it with per-character cursors, and agent `say` lines are tagged `bot`. `say` prints `[name] text` via `game.print`. There is no parsing of addressees. [src] — [chat.lua](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/mod/factorio-mcp/scripts/chat.lua)
- Playbook rule 5: "Human players on the server are spectators. Leave their characters and items alone." Rule 4: "Don't remove or rebuild other characters' buildings unless the planner assigned it". Both are prompt rules only. — [PLAYBOOK.md](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/docs/run4/PLAYBOOK.md)
- Viewing aids for humans: `/follow`, `/follow-cam`, `/follow-cams` (tiled camera windows per agent with status lines) and `/unfollow`. "Humans who join the server need the same mod version installed, because it isn't on the mod portal." — [factorio-mcp README](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/README.md), [follow.lua](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/mod/factorio-mcp/scripts/follow.lua)

## 6. Lessons files: every concrete lesson (directly useful to Claude Crew)

### Takeaway
Four lessons files plus the playbook hold about 70 concrete rules. The highest-value ones for Claude Crew: one owner per module, with the board as the interface contract. Sonnet-medium beats Haiku-low for anything but hauling. Fresh agents per ~200k-token stint with handover notes. Size each job to one stint, with "one target + the measurement that shows done". Measure (10-min production, per-machine status) before acting and follow chains upstream. One item per lane. Copy working cells via in-map export/build blueprint. Lab and science throughput dominates the endgame. Planner checks research % every round. Plan for the API/session window.

### Cited Findings
**Organisation and model choice**
- Give each agent a module to own: it designs, renders, dry-runs, builds, then writes its interfaces into board.md. "The board is the contract… Each area has one named owner." — [lessons-run1.md](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/docs/lessons-run1.md)

- Run 2 mix was 4 Haiku and 30 Sonnet stints. Run 3 used all Sonnet medium. Run 4 used Sonnet medium, with high effort for planning-heavy jobs (`gleba-plan`, `freighter-5/6` are `sonnet/high`). — [lessons-run2.md](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/docs/lessons-run2.md), [agents.tsv](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/docs/run4/agents.tsv)

## 7. linsyking/factorio-mcp as Claude Crew's game-side layer

### Takeaway
factorio-mcp is a substantial, well-tested player-character API. Upstream has 57 tools and ~11k Lua lines. The LPF fork has 71 tools, ~13.4k Lua lines, ~6k test lines, plus Space Age tools. The transport is an RCON remote interface with chunked JSON replies and per-character binding, leases, job chains and news footers. Python `Game`/`Bridge` classes can be driven without MCP. The library is MIT, except route/ (GPL) and calc (AGPL). It could serve as Claude Crew's game layer, but it was built for one-LLM-per-character MCP use. It has no structured work-order or done_when concept, no circuit-network or module/beacon tools, and in the LPF fork a humans-spectate default.

### Cited Findings
- Model: "1 agent ↔ 1 MCP instance (stdio) ↔ 1 character. The character is bound at startup… A binding guard stops two instances from driving the same character." Binding uses a session token plus a lease, with heartbeat and explicit takeover, up to 32 characters by default (the setting goes to 256). Characters are created with `surface.create_entity({ name = "character", … raise_built = true })` and no player. [src] — [factorio-mcp README](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/README.md), [companion.lua](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/mod/factorio-mcp/scripts/companion.lua), [settings.lua](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/mod/factorio-mcp/settings.lua)
- Transport: `remote.add_interface("factorio_mcp", …)` in control.lua. `rpc.lua` responds via `rcon.print(helpers.table_to_json(...))` and chunks large replies (`get_chunk`, 5-minute TTL). The Python client "sends one command and waits for the packet with its id" because Factorio can answer pipelined RCON out of order when a player is connected. Retries are safe for reads and for `enqueue`, which is de-duplicated by `request_id`. [src] — [rpc.lua](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/mod/factorio-mcp/scripts/rpc.lua), [UPSTREAM.md](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/UPSTREAM.md), [PROTOCOL.md](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/docs/PROTOCOL.md)
- Upstream tool count is "Tools (57)" (linsyking README). LPF's is "Tools (71)", grouped as Perception (map_overview, look_around, scan_area, inspect_entity, analyze_factory, map_warnings, alerts, battle_report, production_stats, list_technologies, list_trains…), Blueprints, Chat/events, Instant actions, Jobs (walk_to, drive_to, mine, place_entity, craft_items, insert/extract, set_recipe, set_filters, build_plan ≤100 steps with dry_run, run_plan, wait_until, deconstruct, fight, defend_area, keep_fueled, launch_rocket…), Space Age (platforms, platform_order/build/deconstruct/configure/requests/schedule, landing_pad_requests, ride_rocket, drop_to_planet), Routing (route_belt, route_pipe, trace_belt, measure_belt) and Job control. — [linsyking README](https://github.com/linsyking/factorio-mcp/blob/main/README.md), [LPF factorio-mcp README](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/README.md)
- Known limitations (author-stated): "Not built in: power-pole routing; multi-lane, splitter or balancer synthesis…; throughput/bottleneck analysis beyond `analyze_factory` and `production_stats`; module/beacon upgrade jobs; circuit network settings." — [LPF factorio-mcp README](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/README.md)
- Harness RPCs are callable from Python without a bound character: "Use them from Python (`Game` or `Bridge`: `await game.register_blueprint(...)`, `await game.area_snapshot(...)`)". — [LPF factorio-mcp README](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/README.md)
- Tests: Lua unit tests with a stubbed game API (`tests/mod/*.lua`, about 30 files), pytest against a fake RCON server, and a live 3-agent test (refused second session, parallel walks at vanilla speed, private jobs, fog of war, vanilla mining time). — [LPF factorio-mcp README](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/README.md)
- Maturity signals: upstream went through several "campaign bug report" fix rounds (0.2.9–0.2.13, walker hangs under load, belt-read honesty) inside 3 days. It references an external research workspace (`research/factorio-agent/10..13`, `../BUGS.md`, `11-comparison.md`) that isn't in the repo. Not on the mod portal. — [UPSTREAM.md](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/UPSTREAM.md)
- Policy stance: "Policy-free. Tools describe what they do, never why or when to use them. Planning, delegation, subagents and coordination all live on the agent side." The coordination broker of Agentic-Factorio (`coordinate_*_job`, `assertMayAct`) was removed. — [factorio-mcp README](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/README.md), [UPSTREAM.md](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/UPSTREAM.md)

### Inferences
- Architecturally it is close to Claude Crew's game side: an RCON JSON API with a per-character job queue in the mod. The differences are in emphasis. factorio-mcp is richer in perception, checks, routing and Space Age. Claude Crew has orchestration-facing features (work orders, done_when, coordinator-only reads, human commands, late-game tools such as copy-paste, planners, network and configure).
- The best use is the **LPF fork at 0.3.12** rather than upstream 0.2.22: it has a superset of the tools, the fixes from 4 runs, rpc-log replay and save archive. Upstream has no spectator lock, though.

### Gaps
- Robustness with more than 6 concurrent characters (the "16 agents" cap was never exercised) and UPS impact are unmeasured.
- Behaviour when a human and an agent edit the same entities was never tested.

## 8. Layering Claude Crew onto LPF, or vice versa: fit and effort

### Takeaway
**Recommendation: continue separately and borrow selectively.** Don't rebase. LPF has no orchestrator to rebase onto (it is Claude Code plus markdown), so "adopting" it means only swapping Claude Crew's game-side mod and RCON layer for factorio-mcp. That swap is feasible (MIT, similar architecture), but it is large and would invalidate Claude Crew's benchmark baselines. Porting a targeted set of factorio-mcp features into Claude Crew's mod is cheaper and keeps Claude Crew's distinctive human-multiplayer and orchestration design intact.

### Cited Findings
- LPF's coordination artifacts are prose files: board.md, PLAYBOOK.md, status/<character>.md and agents.tsv. Its scripts are thin RCON helpers (kpi.py, research.py, park_character.py, timelapse.py). [src] — [LPF/scripts](https://github.com/StevenLi-phoenix/llm-play-factorio/tree/main/scripts), [docs/run4](https://github.com/StevenLi-phoenix/llm-play-factorio/tree/main/docs/run4)
- The `Game`/`Bridge` Python API and the `factorio-mcp call` CLI (one process per character, `FACTORIO_CHARACTER`, `FACTORIO_TAKEOVER=1`) let a non-MCP controller drive characters. [src] — [scripts/fa](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/scripts/fa), [game.py](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/src/factorio_mcp/game.py)
- For reference, Claude Crew's local repo (`/home/stephen/dev/factorio-slave`) has ~9.4k Lua lines (`mod/claude-crew`) and ~7.8k Python lines (`crew/`: orchestrator, foreman, controller, actor, orders, late_tools, backends, router, board…). factorio-mcp's mod in LPF is ~13.4k Lua lines. [local count]

### Inferences (effort estimates are rough, for one developer working with agent help)
- **Claude Crew → onto factorio-mcp (replace Claude Crew's mod):** large, about 2–4 weeks. The work: (a) turn off humans-spectate and audit code paths that assume characters have no player; (b) re-implement Claude Crew's job-queue semantics, done_when evaluation and coordinator-only read RPCs as new mod RPCs; (c) port late-game tools (copy-paste, planners, network, configure, diagnose) that factorio-mcp lacks, since circuit network and module/beacon tools are explicit non-goals; (d) re-point Claude Crew's deterministic controller from its RCON API to `Game`/`Bridge`; (e) remove or split out GPL route/ before distributing the mod to friends; (f) re-run benchmark stages S1–S7, because results would shift. Benefit: inherits Space Age, routing, belt tracing, fog of war and provenance. Risk: two divergent forks to track, and the upstream has a bus factor of one and is 4 days old.
- **LPF-style orchestration → onto Claude Crew:** small. LPF's orchestration is "Opus in Claude Code plus a prose board". Claude Crew already supersedes it. The transferable parts are practices: module ownership, handover notes, stint sizing, watchdog agents, and planner research-% checks each round.
- **Claude Crew's distinctive pieces onto LPF (if someone forked LPF instead):** chat @name/@all command routing is medium (1–3 days: chat.lua already logs all player messages, so add a dispatcher plus per-human safety). Structured work orders with in-game done_when checks are medium (2–5 days: extend `wait_until` into a predicate library). The deterministic controller is large (≥1 week, since LPF has none and assumes an LLM per character). The benchmark harness with staged saves and cost tracking is medium (save archive and rpc-log exist; no cost tracking). Model-agnostic backends (DeepSeek via OpenAI-compatible APIs) are medium: factorio-mcp is MCP over stdio, so any MCP-capable client works, but LPF's orchestration is Claude Code-only. Late-game tools are large.
- **Cherry-picking factorio-mcp features into Claude Crew's mod:** each small to medium (see §9). This is the best cost/benefit.

### Gaps
- A fully sized estimate needs a side-by-side of Claude Crew's RPC surface vs factorio-mcp's tools, which this note didn't do.

- **Walking robustness** (`mod/factorio-mcp/scripts/actions/walk.lua`, MIT): wait for every `on_script_path_request_finished` answer, store results by request id, use stuck/no-progress/deadline rules and a coarse fallback search, and expose the pathfinder-budget setting. — [walk.lua](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/mod/factorio-mcp/scripts/actions/walk.lua), [UPSTREAM.md "walker hangs under load"](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/UPSTREAM.md)

- **Reach/approach helper** shared by all actions (`scripts/actions/approach.lua`, including `step_aside` out of a footprint). — [approach.lua](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/mod/factorio-mcp/scripts/actions/approach.lua)

These map directly to LPF's dominant failure class (foreign items on lanes). — [belts.lua](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/mod/factorio-mcp/scripts/belts.lua)

- **Fog of war** (`scripts/vision.lua`). — [vision.lua](https://github.com/StevenLi-phoenix/llm-play-factorio/blob/main/factorio-mcp/mod/factorio-mcp/scripts/vision.lua)
